# فروشگاه آنلاین — پلتفرم تجارت الکترونیک خودمیزبان

**یک پلتفرم کامل فروشگاهی که روی سرور خودتان میزبانی می‌شود.**
ساخته‌شده برای کسب‌وکارهای کوچک و متوسط — روی سرور خودتان نصبش کنید،
مالک داتای خودتان باشید، و به‌راحتی گسترشش دهید.

## ۱. این چیست

یک فروشگاه کامل در یک مخزن کد (مونورپو npm):

- `apps/api` — REST API بر پایه Express.js (TypeScript، ORM پریزما)
- `apps/web` — storefront و پنل مدیریت بر پایه Next.js 14 (App Router، TypeScript)

با یک دستور روی سرور مشتری نصب می‌شود (`./scripts/install-store.sh`)،
با یک دستور در حالت توسعه اجرا می‌شود (`npm run dev`)، و تمام تنظیمات
در یک فایل مستند شده‌اند (`.env.example`).

**از پایه به‌سمت کُردی طراحی شده:** فروشگاه به انگلیسی، کُردی (سورانی)،
عربی و ترکی با پشتیبانی کامل RTL عرضه می‌شود؛ پنل و مستندات همان
زبان‌ها را دنبال می‌کنند.

## ۲. قابلیت‌ها

### فروشگاه (رو به مشتری)

- محصولات: **فیزیکی و دیجیتال** (دانلود با توکن اختصاصی برای هر سفارش،
  محدودیت دانلود و انقضا)، واریانت‌ها، گزینه‌های نوع‌دار (رنگ/سایز...)،
  گالری تصویر، موجودی، سفارش هنگام اتمام موجودی (backorder)،
  اعلان بازگشت موجودی
- مرور دسته‌بندی‌ها (سلسله‌مراتبی)، جستجو، فیلتر چندوجهی، مقایسه،
  «تازه‌دیدها»
- سبد خرید، فهرست آرزوها، نشانی‌ها، تسویه چندمرحله‌ای
- پرداخت: **به‌صورت پیش‌فرض نقدی و واریز بانکی** (مسیر آفلاین،
  تسویه توسط کارکنان)؛ **کارتی با Stripe اختیاری** است، برای هر فروشگاه
- سفارش‌ها: پیگیری، رسید، سابقه سفارش، دانلود محصولات دیجیتال
- بررسی‌ها با عکس، کوپن، کارت هدیه، تخفیف‌ها
- صفحه و وبلاگ: محتوای بلوکی (تیتر، تصویر، ستون، کال‌اوت، نقل‌قول،
  گالری، دکمه) با پیش‌نویس/انتشار و اسلاگ یونیکد
- زبان‌های فروشگاه: en / ku / ar / tr با RTL؛ انتخاب واحد پول و
  پشتیبانی چند ارز
- SEO: متادیتای رندرشده روی سرور، داده ساختاریافته JSON-LD (Product،
  Breadcrumb، WebSite، Article)، نقشه سایت، robots.txt، Open Graph
- سازنده صفحه اصلی (بخش‌ها، بنر، گالری)

### پنل مدیریت (`/admin`)

داشبورد، محصولات، واریانت‌ها، دسته‌بندی‌ها، انبار (موجودی، انبارها،
انتقال، رزرو، شمارش، قوانین بازتأمین، موجودی کانال‌ها)، سفارش‌ها،
مشتریان، بررسی‌ها، کوپن‌ها، کارت هدیه، ارسال (ناحیه و روش‌ها)، مالیات،
صفحات، وبلاگ، **ظاهر (انتخاب تم + توکن‌های طراحی)**، بنر و گالری،
منوها، **تحلیل‌ها (Analytics)**، **وارد/خروجی (Import/Export)**،
تنظیمات، کاربران (نقش: admin، ناظر/مدیر، customer).

### پلتفرم

- **وارد/خروجی گروهی** برای محصولات و دسته‌بندی‌ها (CSV یا JSON،
  پیش‌نمایش، اجرای همه-یا-هیچ) — بخش ۱۰
- **تحلیل و پیشنهاد** (اختیاری، با اولویت حریم خصوصی) — بخش ۱۱
- **سیستم تم**: ۵ تم داخلی، ابزار scaffold، پیش‌نمایش زنده،
  انتخاب به‌ازای هر فروشگاه — بخش ۹
- محدودسازی نرخ درخواست، اعتبارسنجی ورودی با Zod، احراز هویت JWT
  (access + refresh)، هش گذرواژه با bcrypt، کنترل دسترسی مبتنی بر نقش (RBAC)
- سرویس‌های اختیاری به‌نرمی کم‌فایده می‌شوند: بدون Redis → بدون کش؛
  بدون MinIO → بارگذاری روی دیسک محلی؛ بدون SMTP → ایمیل‌ها در لاگ نوشته می‌شوند

## ۴. شروع سریع (توسعه)

**پیش‌نیازها:** Node.js 18+، npm 9+. سرور دیتابیس لازم نیست
(فایل SQLite خودش ساخته می‌شود).

```bash
git clone <repository-url> && cd <repository>
npm install

# دیتابیس: ساخت فایل SQLite + سکیمای کامل، سپس seed کاتالوگ نمایشی
npm run db:deploy        # apps/api/prisma/dev.db
npm run db:seed

# اجرای API (:3001) + فروشگاه (:3000) با هم
npm run dev
```

> **یادداشت برای دیتابیس تازه:** `npm run db:deploy` مایگریشن‌های
> ثبت‌شده را اعمال می‌کند. اگر دیتابیس محلی بعد از تغییر سکیمای
> به مشکل خورد، `npm run db:reset` (ساخت + seed) مسیر مطمئن است.
> ببینید [KNOWN_GAPS.md](../KNOWN_GAPS.md) بخش ۹.

### نقاط دسترسی

| سرویس | URL |
|---|---|
| فروشگاه | http://localhost:3000 |
| API | http://localhost:3001 (`/health` برای سلامت‌سنجی) |
| مدیریت | http://localhost:3000/admin |
| پیش‌نمایش تم‌ها | http://localhost:3000/preview/default (و /minimal، /bold، /dawnlight، /pulse) |

### حساب‌های seed

| نقش | ایمیل | گذرواژه |
|---|---|---|
| مدیر | `admin@store.com` | `admin123` |
| مشتری | `customer@example.com` | `customer123` |

seed یک کاتالوگ نمایشی هم می‌سازد (۵ دسته‌بندی ازجمله `General`،
۵ محصول، بررسی، کوپن، روش ارسال، بنر) و ۵۰ ردیف `UserEvent` ترکیبی،
تا داشبورد تحلیل داده نمونه‌ای نشان دهد — ردیف‌های نمایشی‌اند، نه
داده بازدیدکنندگان واقعی.

### اجرا بدون Docker

همه‌چیز بدون Docker کار می‌کند. فایل‌های compose در `docker/` برای
سرویس‌های **اختیاری** هستند (Redis، MinIO، MailHog، PostgreSQL در صورت
تغییر):

```bash
npm run docker:up      # اجرای سرویس‌های اختیاری
npm run docker:down    # توقف
```

## ۵. پیکربندی

تمام تنظیمات در `apps/api/.env` است (الگو: `.env.example` در ریشه).
مهم‌ترین‌ها:

| متغیر | کاربرد |
|---|---|
| `DATABASE_URL` | `file:./dev.db` (SQLite). باید با `provider` در `prisma/schema.prisma` یکسان باشد — اختلاف، خطای P1012 پریزماست؛ یعنی اشتباه پیکربندی، نه نصب خراب |
| `JWT_SECRET` | ۳۲+ کاراکتر؛ برنامه نصب یک مقدار تصادفی می‌سازد |
| `REDIS_URL` | اختیاری. نبود → کش بی‌صدا غیرفعال می‌شود |
| `MINIO_*` | اختیاری. نبود → بارگذاری روی دیسک محلی |
| `SMTP_*` / `EMAIL_FROM` | اختیاری. نبود → ایمیل‌ها در لاگ نوشته می‌شوند |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` | اختیاری. خالی → پرداخت کارتی پنهان می‌شود، فقط مسیر آفلاین |
| `FRONTEND_URL` | URL کامل فروشگاه (پیوندهای ایمیل، هدایت‌ها) |
| `ANALYTICS_TRACKING_ENABLED` | **`false` (پیش‌فرض).** `true` جمع‌آوری داده رویدادها را روشن می‌کند — بخش ۱۱ و صفحه حریم خصوصی |
| `REVIEWS_AUTO_APPROVE` | `false` (پیش‌فرض). `true` بررسی‌ها را بدون بازبینی منتشر می‌کند |
| `PAYMENTS_ALLOW_MOCK` | `false` (پیش‌فرض). `true` به هر مشتری اجازه تسویه خودی می‌دهد — **فقط دمو** |
| `LOG_LEVEL` / `LOG_FILE` | پیش‌فرض `info`/`logs/app.log` |

### تغییر به PostgreSQL (اختیاری)

1. در `apps/api/prisma/schema.prisma` بگذارید `provider = "postgresql"`
2. `DATABASE_URL` را به نمونه خود نشان دهید، مثلاً
   `postgresql://store_user:store_password@localhost:5432/store_db`
   (فایل compose توسعه از قبل نمونه‌ای با این اعتبارنامه دارد)
3. `cd apps/api && npx prisma migrate dev` برای ساخت سکیمای کامل

کد مستقل از دیتابیس است: فیلترهای ناسازگار با SQLite
(`mode: 'insensitive'`) پرهیز شده و به‌جای آن جستجوی حافظه‌ای
بکار می‌رود؛ پس چیز دیگری تغییر نمی‌کند. برای بهره‌برداری،
به‌منظور پشتیبان‌گیری دیتابیس به‌طور منظم `pg_dump` بگیرید.

## ۷. خلاصه معماری

**مسیر درخواست (فروشگاه):** مرورگر → Next.js (کامپوننت‌های سرور برای
صفحات مهم SEO داده را از API می‌گیرند؛ کامپوننت‌های کلاینت برای
تعامل) → خط لوله middleware اکسپرس (سقف نرخ → تجزیه JSON → احراز
هویت → اعتبارسنجی Zod) → مسیر ماژول → سرویس → Prisma →
SQLite/Postgres.

**پراکسی API → مرورگر:** `next.config.js` مسیر `/api/*` را به API و
`/uploads/*` را به MinIO بازنویسی می‌کند؛ بنابراین استقرار هم‌مبدأ
بدون پیکربندی CORS کار می‌کند، حتی اگر هاست API از مرورگر دسترس‌پذیر نباشد.

**احراز هویت:** `POST /auth/login` توکن **access** + **refresh** کوتاه‌مدت
بازمی‌گرداند. فروشگاه توکن را در `localStorage` نگه می‌دارد (بدون کوکی
ردیابی — بخش ۱۱). نقش‌ها: `admin` (همه‌چیز)، `ناظر/مدیر` (کاتالوگ و
سفارش، بدون مدیریت کاربر)، `customer`.

**مدل داده (هسته‌ای):** کاربران، محصولات (با واریانت، تصویر محصول،
گزینه‌های نوع‌دار)، دسته‌بندی‌ها (درخت خودارجاعی)، سفارش + ردیف‌های
سفارش، پرداخت‌ها، بررسی‌ها (و عکس)، سبد، فهرست آرزوها، نشانی‌ها،
کوپن‌ها، کارت هدیه، ناحیه/روش ارسال، مالیات، انبارها + مدل‌های
انبار، صفحه/وبلاگ (بلوک‌های محتوا)، بنر، منو، تنظیمات فروشگاه،
تنظیمات تم، UserEvents (تحلیل).

**قواعد تاب‌آوری در کل پروژه:** سرویس‌های اختیاری (Redis/MinIO/SMTP)
برای هر قابلیت جداگانه خاموش می‌شوند ولی درخواست را نمی‌افتانند؛
تحلیل هرگز درخواست را نمی‌افتاند؛ نوشتن‌های مدیریتی پیش از رسیدن به
دیتابیس اعتبارسنجی می‌شوند.

## ۸. راهنمای فروشگاه (برای کارپرداز)

- **افزودن محصول**: مدیریت → محصولات → *+ افزودن محصول*. نام، SKU،
  قیمت، دسته‌بندی، تصویر را پر کنید؛ در صورت نیاز واریانت یا گزینه
  بگذارید؛ محصول دیجیتال URL دانلود + سقف می‌گیرد. وضعیت `active`
  آن را منتشر می‌کند.
- **فروش بدون درگاه کارت**: در تسویه، نقدی و واریز بانکی پیشنهاد
  می‌شود. سفارش‌ها با `paymentStatus: pending` می‌آیند؛ کارکنان از
  مدیریت → سفارش‌ها تسویه می‌کنند. (`PAYMENTS_ALLOW_MOCK` را هرگز
  در فروشگاه عمومی روشن نکنید.)
- **فعال‌سازی Stripe**: دو کلید را در `.env` بگذارید، وب‌هوک
  `checkout.session.completed` را در داشبورد Stripe اضافه کنید،
  دوباره اجرا کنید. گزینه کارت خودبه‌خود ظاهر می‌شود.
- **کوپن و کارت هدیه**: مدیریت → کوپن / کارت هدیه. هر دو در تسویه
  کار می‌کنند؛ کارت هدیه کد استرداد می‌سازد.
- **محتوا**: مدیریت → صفحات / وبلاگ — ویرایشگر بلوکی (افزودن تیتر،
  تصویر، ستون، کال‌اوت، نقل‌قول، گالری، دکمه)، پیش‌نویس → انتشار.
  اسلاگ‌ها یونیکد-ایمن هستند (عنوان کُردی/عربی کار می‌کند).
- **صفحه اصلی**: مدیریت → بخش‌های داشبورد + بنر و گالری.

## ۹. تم‌ها

**تم** یک دایرکتوری در `apps/web/themes/<key>/` است:

- `theme.json` — در زمان **build** با سکیمای سخت‌گیرانه Zod اعتبارسنجی
  می‌شود: هویت (key، نام، نویسنده، semver)، `features` (`rtl`،
  `darkMode`، `paid`)، `tokens` (رنگ‌ها، فونت، گوشه، عرض کانتینر،
  سایه کارت، محصول در هر ردیف، کلیدهای بخش‌ها مثل `showTrustBar`)،
  و نقشۀ اختیاری `sections`
- `sections/*.tsx` — جایگزینی کامپوننت بخش‌های صفحه اصلی
  (`hero`، `featured`، `categories`). جایگزینی، بخش پلتفرم را به‌طور کامل
  عوض می‌کند (هنوز حالت «wrap» وجود ندارد).

**تم‌های داخلی (۵):** `default`، `minimal` (پولی، متن‌محور، serif)،
`bold`، `dawnlight`، `pulse`.

**مسیر توسعه برای تم نو:**

```bash
node scripts/scaffold-theme.mjs solar --name "Solar"
```

scaffold همه نقاط ثبت را انجام می‌دهد (theme.json + سه نمونه‌ی اولیه‌ی بخش
سازگار با قرارداد و RTL، ورودی رجیستری، نقشه کامپوننت، ماتریس تست
RTL، تست انتخابگر تم). سپس توکن‌ها و بخش‌ها را ویرایش کنید؛
`theme.json` خراب **build** را با مسیر خوانا شکست می‌دهد؛ فراموشی
ثبت RTL مجموعه تست را شکست می‌دهد. در `/preview/solar` پیش‌نمایش کنید؛
برای هر فروشگاه در **مدیریت → ظاهر** فعال کنید. پوش‌اوورهای توکن هر
فروشگاه روی تم فعال سوار می‌شوند.

**محدودیت‌ها (صادقانه):** تم‌ها با پلتفرم نسخه‌گذاری می‌شوند (بازبینی
کد، نه بارگذاری بلادرنگ)؛ `paid: true` فقط متاداتاست (هنوز سنجش لایسنس یا بازار وجود ندارد)؛ `darkMode` فقط نشانۀ قابلیت است.

## ۱۰. وارد/خروجی گروهی

فقط admin + ناظر/مدیر. UI در `/admin/import-export`؛ API در
`/api/import-export`.

- **خروجی** — `GET /export/:entity?format=csv|json&sample=1` برای
  `products` (با واریانت، تصویر، فیلدهای SEO) و `categories`
  (با پیوند والد). `sample=1` یک ردیف الگویی برمی‌گرداند.
- **پیش‌نمایش** — `POST /preview {entity, format, text}`: تجزیه +
  اعتبارسنجی، طبقه‌بندی هر ردیف به **ساخته‌شده / به‌روزرسانی‌شده / خطا**،
  هیچ چیزی نمی‌نویسد.
- **اجرا** — `POST /commit`: فایل واقعی را دوباره اعتبارسنجی کرده و
  **همه-یا-هیچ** در یک تراکنش اعمال می‌کند. خطای حتی یک ردیف → هیچ
  چیزی اعمال نمی‌شود.

قاعده‌ها: محصولات با **SKU** تطبیق می‌یابند (نو → ساخت، موجود →
به‌روزرسانی، خانه‌های خالی نادیده گرفته می‌شوند)؛ دسته‌بندی‌ها با
**اسلاگ، سپس نام** (بی‌تفاوت به بزرگ/کوچک‌نویسی)؛ ستون‌های
`variants`/`images` اگر موجود باشند، قبلی‌ها را به‌طور کامل جایگزین
می‌کنند. محصول بدون ستون `category` به دسته‌بندی seedشده `General`
می‌رود. سقف: ۱٬۰۰۰٬۰۰۰ نویسه / ۲٬۰۰۰ ردیف برای هر فایل.

با ۲۹ تست یکپارچه، ۱۴ تست واحدی parser CSV، ۱۲ تست کامپوننت صفحه
مدیریت و اسکریپت زنده CI `scripts/verify-import-export.py` تأیید شده است.

## ۱۱. تحلیل، پیشنهاد و حریم خصوصی

**پیش‌فرض خاموش.** کل خط رویدادها فقط وقتی فعال می‌شود که API با
`ANALYTICS_TRACKING_ENABLED=true` اجرا شود؛ بدون این پرچم، مسیرهای ردیابی
404 برمی‌گردانند و **هیچ چیزی جمع‌آوری نمی‌شود** (درخواست‌های رویدادی
فروشگاه بی‌صدا دور انداخته می‌شوند).

وقتی روشن است:

- **رویدادها**: `view`، `add_to_cart`، `wishlist` از فروشگاه
  (شناسۀ نشست از `sessionStorage` — هرگز کوکی نیست؛ توکن bearer فقط
  وقتی کاربر وارد شده است پیوست می‌شود و رویدادها را به حساب می‌بندد)؛
  `search` و `purchase` سمت سرور ثبت می‌شوند (مسیر جستجو، ساخت سفارش).
  هر رویداد نوع رویداد، محصول/دسته‌بندی، متن جستجو، زمان، user agent
  و IP کلاینت را ذخیره می‌کند.
- **مصرف‌کننده‌ها**: **Trending** صفحه اصلی (بنیاد رویدادها)،
  **فعالیت فروشگاه** در مدیریت (شماره‌های امروز، پرتکرارترین
  جستجوهای ۳۰روزه، ترند ۷روزه)، **نرخ تبدیل** هر محصول
  (بازدید → سبد → خرید)، رفتار کاربر، و **موتور پیشنهاد**
  (also-bought از هم‌خریدهای واقعی می‌آموزد؛ پیشنهاد مبتنی بر تاریخچه
  از بازدیدها).
- **هرگز نمی‌کنیم**: به‌صورت پیش‌فرض هیچ تحلیل سومی؛ (Google Analytics
  فقط اگر صاحب فروشگاه property id پیکربندی کند)، فروش یا اشتراک‌گذاری
  داده، کوکی ردیابی — وضعیت ورود و ترجیحات در `localStorage` مرورگر است.
- **لاگ سرور** همواره IP کلاینت را دارد (لاگ استاندارد وب)؛ متن
  جستجو فقط در `LOG_LEVEL=debug` در لاگ ظاهر می‌شود.

صفحه `/privacy` همه این‌ها را مستند می‌کند و یادداشت نگهداری دارد:
اگر رفتار تغییر کند، صفحه در همان کامیت تغییر می‌کند.

## ۱۲. خلاصه API

REST، JSON، در صورت نیاز محافظت‌شده با JWT. URL پایه: `/api`.

- **احراز هویت**: ثبت‌نام، ورود، refresh، خروج، me، فراموشی/بازنشانی گذرواژه
- **محصولات**: فهرست (فیلتر چندوجهی + جستجو)، منتخب، `search`،
  بر اساس id/slug، مرتبط، CRUD (مدیر)، واریانت‌ها و گزینه‌ها
- **سفارش‌ها**: فهرست، ساخت، به‌روزرسانی وضعیت (مدیر)، لغو، رسید،
  پیگیری، توکن دانلود برای هر ردیف
- **پرداخت**: process (تسویه کارکنان)، Stripe Checkout + وب‌هوک
- **کاربر / مشتری**: CRUD (مدیر)، سفارش و فهرست آرزوی هر کاربر
- **کار کاتالوگ**: دسته‌بندی‌ها (درخت)، انبار و انبارها، کوپن،
  کارت هدیه، ارسال، مالیات
- **محتوا**: صفحات، وبلاگ، بنر، منو، بخش‌های صفحه اصلی، تنظیمات، تم
- **کار فروشگاه**: `import-export` (بخش ۱۰)، `analytics` (بخش ۱۱)،
  `recommendations` (ترند، تازه‌ها، also-bought، bought-together،
  تاریخچه، شخصی‌سازی‌شده)، `downloads`، `currency`، `storage` (بارگذاری)
- **سلامت**: `GET /health`

منبع ارجاع‌پذیر: `apps/api/src/modules/*/…routes.ts` (هر مسیر یا
تست واحدی/یکپارچه دارد یا با اسکریپت زنده `verify-*.py` پوشش داده
شده است).

## ۱۳. دیتابیس

**پیش‌فرض: SQLite** (`apps/api/prisma/dev.db`) — نصب صفر؛ فایل با
`npm run db:deploy` ساخته می‌شود. PostgreSQL به‌طور کامل پشتیبانی
می‌شود (بخش ۵).

```bash
npm run db:deploy     # اعمال مایگریشن‌ها (migrate deploy)
npm run db:migrate    # توسعه: ساخت/اعمال مایگریشن
npm run db:seed       # کاتالوگ نمایشی + حساب‌ها
npm run db:reset      # حذف، ساخت دوباره، seed
npm run db:studio     # رابط گرافیکی Prisma Studio
npm run db:generate   # بازسازی کلاینت پس از ویرایش سکیمای
```

کاستی شناخته‌شده: مجموعه مایگریشن ثبت‌شده از برخی تغییرات سکیمای اصلی
دیرتر است (وضعیت صادقانه در [KNOWN_GAPS.md](../KNOWN_GAPS.md) بخش ۹) —
برای دیتابیس محلی نو، `db:reset`/`prisma db push` + seed مسیر مطمئن است.

## ۱۴. تست و CI

| مجموعه | دستور | نیاز |
|---|---|---|
| واحدی API | `npm run test:api:unit` | هیچ (Vitest) |
| یکپارچه API | `npm run test:api:integration` | هیچ — **mock-Prisma** حافظه‌ای، بدون دیتابیس |
| lib وب | `npm run test:web:lib` | هیچ (Vitest + happy-dom) |
| کامپوننت وب | `npm run test:web:components` | هیچ (RTL + happy-dom) |
| regression زنده (API) | `bash scripts/regression.sh` | API اجراشده + داده seed |
| regression زنده (مرورگر) | `ui-checks` CI | API + فروشگاه buildشده، Playwright |
| بررسی‌کننده‌های قابلیت | `python3 scripts/verify-*.py` | API اجراشده (+ فروشگاه برای موارد مرورگری) |

CI (`.github/workflows/ci.yml`) با هر push به `main` دو job موازی اجرا
می‌کند: **api-checks** — بررسی الگوی محیط، مایگریشن، seed، اجرای
API، `regression.sh`، `audit-silent-writes.py`، `verify-commerce.py`
و `verify-import-export.py` — و **ui-checks** — `next build`، اجرای
API + فروشگاه، سپس مجموعه‌های Playwright: پیمایش صفحات، سازنده صفحه
اصلی، بنر، گالری، کدهای خطای 404، حفاظت‌های نقش کاربر، اعداد
داشبورد، صفحات + نوار کناری، وبلاگ، هندسه نوار کناری، اسلاگ یونیکد.

## ۱۵. استقرار

**نصب مشتری (توصیه‌شده):** روی میزبان Docker —

```bash
git clone <repo> /opt/store && cd /opt/store
./scripts/install-store.sh     # compose (پروفایل بهره‌برداری) + seed، یک دستور
```

برنامه نصب یک `JWT_SECRET` تصادفی تازه می‌سازد،
`docker-compose.prod.yml` را build می‌کند (api + web + postgres + redis +
minio + mailhog)، در اولین راه‌اندازی دیتابیس را همگرا می‌کند و seed را
از داخل کانتینر API اجرا می‌کند. جزئیات کامل:
**[DEPLOYMENT.md](DEPLOYMENT.md)** (حالت A Docker، حالت B
بدون Docker).

**دستی:** `npm run build && npm run start` (یا Dockerfileهای
`Dockerfile.api` / `Dockerfile.web`). فروشگاه را پشت TLS بگذارید؛ پیش از
راه‌اندازی عمومی `FRONTEND_URL`، `CORS_ORIGIN`، SMTP و (اختیاری) Stripe
را در `apps/api/.env` بگذارید.

## ۱۶. عیب‌یابی (فشرده)

| نشانه | علت و رفع |
|---|---|
| `the URL must start with the protocol 'file:'` (P1012) | `DATABASE_URL` با `provider` سکیمای کامل یکی نیست (sqlite به `file:` نیاز دارد). هم‌خطشان کنید — اشتباه پیکربندی است، نه نصب خراب |
| فروشگاه کار می‌کند ولی «صفحه یافت نشد» برای صفحه منتشرشده | فقط **404 قطعی API** not-found می‌دهد؛ خرابی API صفحه خطای موقتی نشان می‌دهد (fail-open، عمداً) |
| 500 برای PDP هنگام درخواست | `og:type` را بررسی کنید — Next.js `"product"` را نمی‌پذیرد؛ کد از مقدارهای مجاز استفاده می‌کند |
| صفحه مدیریت بدون داده رندر می‌شود | API اجرا نمی‌شود یا `NEXT_PUBLIC_API_URL` به هاستی اشاره می‌کند که مرورگر نمی‌رسد — اپ وب `/api` را هم‌مبدأ پراکسی می‌کند (بخش ۷) |
| گزینه کارت در تسویه نیست | کلیدهای Stripe گذاشته نشده (یا وب‌هوک نیست) — مورد انتظار است: فروشگاه به مسیر آفلاین برمی‌گردد |
| ایمیل‌ها «فرستاده نشدند» | SMTP پیکربندی نشده → در لاگ نوشته می‌شوند (`LOG_FILE` را بررسی کنید). در محلی MailHog استفاده کنید |
| داده قدیمی بعد از تغییر سکیمای کامل | محلی: `npm run db:reset`؛ برای مجموعه مایگریشن: `scripts/sync-migrations.sh` |

تاریخچه کامل رفع‌ها در git است؛ کاستی‌های کنونی در
[KNOWN_GAPS.md](../KNOWN_GAPS.md) است.
